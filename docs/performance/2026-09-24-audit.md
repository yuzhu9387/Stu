# Stu 页面性能检查（2026-09-24）

主要瓶颈是页面切换反复卸载工作区、重新获取完整数据，以及不相关的界面交互触发整页渲染。已优化并保留原有网址。

## 测量方法与范围

- 覆盖主应用的 Plan（Adjust）、Calendar、Fridge、Recipes、Settings（guidance）、Knowledge、Weekend prep 七个页面。
- CPU 对比：React 开发版 Profiler + jsdom，同一合成数据集（120 道食谱、60 项库存、13 周菜单），每页运行五次，丢弃首次，取剩余四次中位数。初次渲染一列包含加载后的 React 提交耗时之和。
- 数字不包含网络、浏览器布局、图片解码和绘制，不能当作用户实际的点击到显示时间，也不是线上生产环境的 INP/LCP。几毫秒差异可能来自测试波动。
- Knowledge 的合成数据没有长篇文档；没有据此推断大型知识库的搜索性能。账号、分享、旧版导入等非主导航页面没有做完整 CPU 对比。
- 本机已运行的生产服务：七个主页面 HTML 响应暖缓存中位数约 1.6–3.5 ms；这只代表 HTML 服务时间，不含后续数据加载。
- 对真实数据库仅做只读统计：18 道食谱、14 项库存；测量时 11 个菜单版本。厨房对象序列化约 411 KB；仓储读取暖缓存中位数 45.07 ms（5 次，范围 39.17–69.31 ms），首次 119.25 ms。没有修改用户数据。此数值也不包含 HTTP 序列化/传输。

## 已实施

1. 七个主路由共用持久布局，保留厨房数据、命令状态和 AI 任务订阅。连续切页只加载一次厨房数据；浏览器聚焦、保存和 AI 完成后的数据刷新仍保留。刷新浏览器或进入其他路由组仍会正常重新加载。
2. 头像菜单维护自己的展开状态。Plan 分析、规则提示、备餐计算和 Calendar 库存不足计算仅在依赖数据变化时重新执行。复用日期格式化器。
3. 导航按钮在鼠标悬停/键盘聚焦时预取目标路由；显式处理持久布局下的切页滚动。浏览器后退不覆盖原有滚动恢复；跨页面自动清理抽屉、临时错误与提示。
4. Recipes 首次展示 24 张卡片，通过 Show more 每次追加 24 张。搜索、标签、餐次和排序覆盖全部食谱；筛选后从第一批开始，已有勾选保留。当前 18 道食谱仍一次显示。卡片列表独立渲染，图片按卡片/抽屉实际宽度选择资源。

持久布局与路由预取采用 Next.js 的公开机制：[布局与状态保留](https://nextjs.org/docs/app/getting-started/layouts-and-pages)、[导航与预取](https://nextjs.org/docs/app/getting-started/linking-and-navigating)。

## 验证

- 新增跨路由持久化回归：七页之间不重复请求厨房数据、不重新订阅同一 AI 任务；聊天草稿保留；窗口聚焦仍刷新；浏览器历史导航不会残留旧抽屉。
- 新增食谱列表回归：分批显示、搜索屏幕外食谱、勾选跨筛选保留。
- 使用隔离的合成数据 API 与同一份前端代码验证真实浏览器路由，避免操作用户家庭数据：七页可达、正常切页回到顶部、后退恢复滚动；浏览器无控制台错误。该浏览器检查使用开发服务器，只用于行为验证，不计入 CPU/生产响应数字。
- 性能改动版本：完整前端测试 158 项通过，新增历史导航/滚动断言后定向 17 项通过；TypeScript、ESLint 与生产构建通过。13107 前端容器已重启，健康检查正常，Recipes 返回 HTTP 200。
- 工作区另有 Desgin 任务同时编辑规划/抽屉功能；本报告的数字对应本次性能改动快照，不包含随后新增功能的性能影响。16:07 UTC 对进行中的工作区检查时，TypeScript 已通过；全量测试有 4 项失败，其中本次持久化测试原先写死两个任务类型，现已适配新增的 fulfillment 类型。其余 3 项属于正在修改的餐点按钮与确认界面断言（kitchen-meal-drawer、kitchen-setup-choices、kitchen-workspace），未覆盖或回滚其他任务代码，不能据此声称最新共享工作区全部测试通过。已上线的性能快照独立构建成功。

## 后续空间

- 当前 Fridge、Settings、Knowledge、Prep 没有测出明显 CPU 热点，不需要继续增加复杂缓存。
- Plan 仍是较重的页面。菜单历史变多后，可继续测量并限制隔天重复检查需要遍历的历史范围；本次没有更改规则含义。
- 厨房数据仍为完整快照；后续若图片来源、聊天记录或知识库内容持续增长，可分开列表摘要与详情，减少首次加载和每次保存的响应体。当前已先消除最频繁的跨页重复下载。

## 复测

在 `web` 目录运行：

```sh
KITCHEN_BENCHMARK=1 KITCHEN_BENCHMARK_OUTPUT=/tmp/stu-render-benchmark.json pnpm exec vitest run tests/kitchen-performance.test.tsx
```

基准默认不参加普通测试，无运行时性能埋点。运行时不要并行构建或执行完整测试，以减少 CPU 争用。原始前后数据保存在同目录 `2026-09-24-render-benchmark.json`。
