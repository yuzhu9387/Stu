# 以冰箱为中心的 Stu：设计

日期：2026-09-28 · 状态：待审

## 1. 目标

现在的 Plan、Calendar、冰箱、菜谱各管各的，"让 AI 排一周"不好用，维护菜谱也嫌麻烦。
这次把整个 app 改成围绕冰箱：打开就是冰箱，排餐、做饭、补货都从冰箱出发，AI 只帮小忙。

成功的标准：一周里的每件事都能从冰箱首页一两步到达；不用维护菜谱也能顺利排餐和做饭；电脑和手机都好用。

## 2. 依据：家里的一周

1. **补货**（周中，不定期）：发现储备少了就集中买一波，补齐冰箱。主要是每日必需品（牛奶、鸡蛋），加上下周想做想吃的。
2. **周末现做**：打开冰箱看有什么，挑些肉做周末吃的，顺便多做一些冻起来，留到周中吃。
3. **周日排下周**：把冷冻室里的菜往日历上放，注意营养搭配、不浪费。
4. **周中执行**：按计划做饭，吃掉的从冰箱扣掉。偶尔有变化，要能快速记一笔。
5. **菜谱**：刷视频看到能做的就加进来；想消耗某种食材时搜一下。
6. **AI**：只做小事，比如生成简单步骤、看看冰箱、推荐百搭快手菜。

## 3. 已定的决定

- 首页就是现在的冰箱页，外观不变。
- 冰箱右边从上到下是：一本小书（Recipes）、📅 Calendar 圆按钮、📋 Plan 圆按钮。点了跳到对应页面，这些页面的布局不变。手机上三个按钮悬浮在右下角。
- 没有顶部导航。Calendar、Plan、Recipes 页面左上角有 "← 冰箱" 返回；设置仍在右上角头像菜单里。
- 购物清单是一张贴在冰箱门上的便签。没有自动提醒。
- 冰箱里可以多选食物，选中后底部只出现一个按钮 **🔪 + Prep**（悬停提示 "Add to prep day"）。
- 一次 + Prep 就是一道菜。周末吃掉的份数不记；做完只手动填"多出来的份数"，默认进冷冻室。日历不动。
- Calendar 页的抽屉是做饭用的：✓ Done、✗ Skip、↺ Changed。Changed 只有一个可选的备注框。
- Plan 页的抽屉直接进编辑，按菜分组；保留从冰箱或菜谱选菜，以及每道菜消耗几份；空着的栏位保存时由 Stu 补全。补全的内容只属于这一餐，**不存进菜谱书**。
- 菜谱来源：文字、图片、小红书、B站、YouTube/Instagram 链接。
- 每个环节电脑和手机都会用。

## 4. 设计

### 4.1 冰箱首页与导航

- `/` 和 `/fridge` 都打开冰箱页（原来 `/` 跳到 Calendar）；demo 同样以冰箱为起始页。
- 冰箱页保持现有布局：标题、短缺提示、深色 "Kitchen Fridge"（Group / Sort）、冷冻和冷藏分区、按营养类分行的架子。
- 右侧栏从上到下：
  - 📖 小书：Recipes。
  - 📅 圆按钮：Calendar，打开本周。
  - 📋 圆按钮：Plan，打开计划页现在的步骤。
- 手机上右侧栏变成右下角的悬浮按钮组，滚动时一直显示。
- 去掉 workspace 顶部的四个标签（Main navigation）。Logo 和头像菜单保留，点 Logo 回冰箱。
- 其他页面：
  - Calendar、Plan、Recipes（列表和详情）、Prep、Settings 的标题左侧加 "← 冰箱"。
  - Prep 页的 "← 冰箱" 回到冰箱；从 Plan 进入时，保留原来回 Plan 的入口。
  - 页面内容本身不变。

### 4.2 Plan 编辑抽屉（在 Plan 页点卡片）

- 点卡片直接打开编辑，不再先进详情。
- 每道菜一张卡，从上到下：
  - **菜名**。
  - **来源**：冰箱里的一样东西 / 一个菜谱 / 🧺 Make your own。
  - **消耗几份**。
  - **营养**：主类 + Also contains。
  - **食材**：选了菜谱就显示菜谱的；否则是这道菜自己的食材表（可编辑）；冰箱里的成品菜不需要。
  - **步骤**：这道菜在这一餐里的步骤。
  - **准备时间**：选了菜谱就用菜谱的；否则是这道菜自己的时间；冰箱成品菜是加热时间。
- 卡片下面：+ Add dish、🧺 Make your own、Choose recipe。整餐的日期、餐次、总时间放在抽屉最上方。
- **保存时补全**：
  - 有空栏位（没有食材、步骤、时间或营养）的菜，保存前先请 Stu 补全，按钮会写出要补几处（"Save · Stu fills 3 blanks"）。
  - 补全的食材、步骤、时间、营养只存在这一餐的这道菜上，**不存进菜谱书**。购物清单和耗时计算会用到这道菜自己的食材和时间。
  - 想留下来的话，抽屉里仍有 "Save to recipe 📖"，手动存进菜谱书。
  - Stu 失败或超时：照常保存，空栏位留空，提示"之后可以再补"。
- 删除一道菜会连它的步骤一起删（现有的 `removeComponent`）。
- 键盘 Delete 删整餐（已上线的 A1）不受影响；在输入框里按键不算。

### 4.3 Calendar 做饭抽屉（在 Calendar 页点卡片）

- 就是现在的详情视图：按菜分块，写明每道菜是现做还是加热、食材和步骤，外加 Ingredients 勾选。
- 顶部三个按钮：
  - **✓ Done**：照常从冰箱扣掉计划用的库存。
  - **✗ Skip**：照常不扣。
  - **↺ Changed**：弹出一个备注框，可写可不写（例如"改成了包子"），确认后这餐记为 Changed，**不自动扣冰箱**，实际吃掉的东西你到冰箱里改。卡片和详情里会显示 "Changed" 和备注。可以像 Done 一样撤销。
- "Edit meal" 仍然在这个抽屉里，用于临时改计划。

### 4.4 🔪 + Prep 与 Prep day

- 冰箱多选：电脑上点卡片左上角的圆点进入多选；手机上长按一样东西进入多选。单点仍然打开这样东西的详情。选中后底部出现一条操作栏："2 selected · 🔪 + Prep · ✕"。
- 点 + Prep：
  1. 用选中的食材请 Stu 出一道菜（复用 compose：菜名、用量、步骤、时间、营养），也可以改成现有菜谱或改名。
  2. 这道菜成为**本周末 prep day** 的一个 prep 任务：名字、步骤、时间都存在任务上，inputs = 各食材要用的份数。Stu 出的菜**不存进菜谱书**；选了现有菜谱时才带 recipeId。
  3. 本周末的 prep day 属于下周的计划（和现在的 Prep 页一致：下周一之前的那个周末）。下周还没有计划时，先建一个只有 prep、没有餐的草稿计划。
- Prep day 页：每道菜一张卡，显示来源食材、步骤、时间，加上 ✓ Done / Remove。
  - Done 时只问一个数：**多出来几份**（默认 0），以及放哪里（默认 ❄️ 冷冻，可切 🧊 冷藏）。
  - 引擎：prep 完成时扣掉 inputs；多出来的份数作为一盒成品进指定位置（名称 = 菜名，日期 = 今天）。0 份就不建盒子。
  - 撤销：沿用 prep.status 现有的撤销。
- 现有从计划自动生成的 batch prep 继续保留，和 + Prep 出来的任务放在同一个列表里。

### 4.5 购物清单便签

- 冰箱左上角贴一张便签，显示前两三样和总数；手机上是冰箱标题栏右边的 "🛒 5"。点开是清单抽屉：
  - 一行一个东西，可以带数量（"牛奶 2"）；随手加、改、删，可以勾"已买"。
  - **Put in fridge**：勾过的东西一次入库。入库前可以改位置和份数，默认冷藏、1 份；数量写成数字时，份数就用这个数字。同名食物沿用已有的类型和 emoji；新东西类型默认 Other。入库后这些行从清单上消失。
- Plan 页里按计划算出来的购物清单（Shopping & prep）保留不动。

### 4.6 菜谱：导入与搜索

- 导入：Recipes 页的 Import 除了文字和图片，再加一个"贴链接"。
  - 服务器读取链接页面上公开的内容：标题、描述或正文，页面元数据；YouTube 和 B站能拿到字幕的也读。Stu 整理成菜谱草稿（现有的 extract），你在导入确认页里确认或修改后保存。
  - 读不到时（小红书经常这样），提示"这个链接读不到，请粘贴文字或截图"，不保存任何东西。
  - 安全：只允许 http/https 的公网地址（拒绝内网和本机地址，每次重定向后都重新检查）；限时 10 秒；最多读 2 MB；不执行页面脚本。
- 搜索：现有搜索框按菜名、食材、标签搜。另加一个 "Uses my fridge" 开关，把用到冰箱里现有食材最多的菜排在前面，并显示"冰箱里有 3/5 样"。
- 菜谱可以不填全，保存时 Stu 补全空着的部分（和 4.2 用同一个补全接口）。

### 4.7 Stu 的角色

- **补全**：保存一餐或菜谱时补全空着的栏位（4.2、4.6）。
- **+ Prep 出菜**：给选中的食材起名、写用量和步骤（4.4）。
- **在冰箱页问 Stu**：冰箱页有一个小输入框，比如"今晚吃什么？"，Stu 根据冰箱里的东西和常做的快手菜（标了 Quick 的菜谱）回答，只给建议、不改任何数据。
- Plan 页的 Stu 聊天和"生成一周"保留，但不再是主流程。

## 5. 数据与接口改动

| 改动 | 说明 |
|---|---|
| Meal 状态加 `changed` | meals.status 是普通字符串列（String(16)），不是 Postgres 枚举，所以不需要枚举迁移，只在代码里的 ExecutionStatus 加一个值；引擎 `meal.status` 接受 changed，不扣库存，可以撤销；分析和统计把 changed 当作"没按计划"。 |
| Meal 加 `note` | 可选，最多 500 字，存在 meals 表新列里（迁移）。 |
| prep 完成可指定位置 | `prep.status` 接受 `location`（freezer / fridge），`actualPortions` 可以是 0。 |
| 一道菜自己的信息 | MealComponent 加可选的 `ingredients`（同菜谱的食材格式）和 `activeMinutes` / `elapsedMinutes`；存在 meal_components 的新 JSON 和数字列（迁移）。没有菜谱的菜，购物清单用它自己的食材，耗时计算用它自己的时间；菜谱的优先。 |
| 补全接口 | `POST /api/v1/kitchen/fill`：输入一餐的草稿（每道菜已有的信息），返回每道菜补全后的食材、步骤、时间、营养；只预览、不保存，也不建菜谱。demo 用确定的假数据。 |
| + Prep | 前端组合现有能力：compose → prep.save（下周计划不存在时先 plan.save 一个空草稿）。不建菜谱。 |
| 购物清单 | 工作区新增 `shoppingList: [{id, name, quantity?, checked}]`，关系表 `shopping_note_items`（迁移 0037；旧的计划模块已经占用了 `shopping_items` 这个表名）；命令 `shopping.save`、`shopping.delete`、`shopping.putAway`（一次建好冰箱条目并删掉这些行）。 |
| 链接导入 | `POST /api/v1/kitchen/import-link {url}` → 抓取、清理成文字 → 复用 extract。 |
| 问 Stu | `POST /api/v1/kitchen/ask {message}` → `{reply}`；只读。 |
| MCP | `kitchen_command` 自动支持新命令；`kitchen_read` 会带上 shoppingList。 |

## 6. 出错与边界

- AI 相关（补全、+ Prep 出菜、链接导入、问 Stu）失败时都说明原因，已经填好的内容不丢；补全失败照样保存。
- + Prep 选中的东西已经没有剩余份数时不能选；compose 用到的份数永远不超过库存（已有的限制）。
- Put in fridge 时同名合并规则沿用 `inventory.receive`。
- 去掉顶部导航后，每一页都要能回到冰箱；深链接（`/calendar?week=…&meal=…`）照常能打开。

## 7. 测试

- 后端：changed 状态（不扣库存、可撤销、迁移）、note、prep 完成指定位置和 0 份、购物清单命令和入库、fill / import-link / ask 接口。链接导入要测：拒绝内网地址、重定向到内网、超时、超大页面。
- 前端：冰箱页右侧按钮和返回、多选 + Prep、Prep day Done、便签清单入库、两个抽屉的分工、保存时补全、Uses my fridge 排序。
- e2e：`core-flow.spec.ts` 现在依赖顶部导航，要改成从冰箱首页的按钮进入。
- 每一步都在 `/demo` 里用桌面和手机宽度看一遍。

## 8. 实现顺序

每一步单独做完、测试、给你看，再做下一步：

1. 冰箱首页：右侧小书和圆按钮、去掉顶部导航、"← 冰箱"、`/` 打开冰箱、e2e 跟着改。
2. 两个抽屉：Plan 编辑（按菜分组、来源、份数、保存时补全和 fill 接口）；Calendar 做饭（Done / Skip / Changed，加 note 和 changed 状态）。
3. 🔪 + Prep：冰箱多选、Prep day 卡片、完成时填多出来的份数和位置。
4. 购物清单便签。
5. 菜谱：链接导入、Uses my fridge。
6. 冰箱页问 Stu。

## 9. 这次不做

- 必需品自动提醒、按消耗推算库存。
- 记录周末吃掉的份数、把周末的份数自动放进日历。
- 视频语音转文字（只读页面上已有的文字和字幕）。

## 10. 假设（审的时候请特别看）

- ~~补全的菜自动存成菜谱~~ → 已改：补全和 + Prep 出的菜都不存进菜谱书，只存在这一餐或这个 prep 任务上。
- + Prep 加到"下周计划"的 prep day（即本周末），和现有 Prep 页的对应关系一致。
